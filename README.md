### 代码说明
- 代码里有很多💩，批判性阅读。

- 一份上、下主控代码通用三台车，通过Config/rp_config.h里的宏来选是哪辆车的代码，耦合性比较高，其实比较恶心，好处是防止一份代码改了某些东西但是另一份代码忘记改。
- 有一些没用的宏定义代码可以自己删掉方便阅读。
- can_protocol.c的CAN_Send函数是最终发给电机电流的函数，可以从这里入手看各个电机的输出是哪里来的。
- Device/motor.h文件说明了电机的ID和放在哪个CAN上。
- 各个module是通过car_move_mode、特殊flag来决定执行什么逻辑以及电机用哪种pid类型输出。
-  chassis驱动是通过板间通信，上主控发给下主控底盘运动目标，下主控再进行功率限制等处理。
- 板间通信有的内容没用到，后面根据自己规划写。
- 视觉有UI画出识别装甲板的圈圈，但是后来的车相机和图传位置不一样，所以画的位置不太对，没更新。
- UI用的周佳慧的顶级开源[Priority_UI](https://github.com/IsaacZH/Priority_UI)
- 下主控写了无线充电代码，但是英雄没规划装无线充电。
## 踩过的坑
- 如果一份之前正常的代码突然出现电机偶尔乱转的情况，不一定是代码逻辑问题，也可以看看是不是can负载比较高导致电机乱转。

- 之前试过有一个图传pithc舵机坏了导致整个主控的can、遥控器接收机异常，拔掉那个坏的舵机就恢复正常了，出现很奇怪的问题首先可以看看是不是硬件层出现了问题，再看软件。
- 布线的时候线的接头处一定要用扎带固定好，防止接口被扯松，特别是线材外露的地方一定要做好保护。
- 写代码的时候还是要想想怎么写更优雅，因为有很多功能都是后来需要加上去的，留好接口，多写标志位，多写结构体。
- 写了的、要上场的功能一定要测试。
- 新弹丸省着点用，新弹丸散布会比旧弹丸好很多，新弹丸用来检验而不是测试。
- 电控方面pitch和yaw要调得很稳，才能测散布，pitch稳态误差0.2°以内，发射抖动在0.5°以内。
- 测散布很牢，做好心理准备。
- 大弹丸比较容易过被动限位，所以写了个卡摩擦轮处理以及最后一发弹丸不发射。

## 未来可优化的地方

- 多想一下怎么才能更智能、更自动化，场上很有可能就发挥作用了。例如检测基地装甲板打开就自动低头类似这些。
<div align="center">

![](https://raw.githubusercontent.com/iverson333333/github_image/refs/heads/master/2025_HERO/auto_low_head.png)

自动瞄准底部装甲板

</div>

*其实还可以写一个自动更新吊射角度的程序，吊射命中在一定条件下自动记录pitch角度，这样就能在下次吊射时对位更快了*。

- 吊射部分虽然可以实现功能，但写的逻辑还是比较乱的，例如有一些不必要的标志位，以及一个函数里包含了很多东西。

- 3508拨盘每次比赛前都要人工重新复位，后面如果可以用DM4310或者加光电门就可以全自动了。
- UI部分还可以再弄好一点，比如整车电机的在线状态，模块是否正常工作，可以用线条画出来，在比赛时相当于日志的作用，对于赛后找问题来说很重要。
<div align="center">

![](https://github.com/iverson333333/github_image/blob/master/2025_HERO/UI.png?raw=true)
UI说明

</div>
- 一定要熟读规则手册，不能犯经验主义。例如交流赛的时候打不出弹，一直以为是裁判系统问题，结果最后发现联盟赛规则的热量是100，超级对抗赛是200。
